# SiteVantage

[![iOS Build & Test](https://github.com/sanaddmour-byte/project-M/actions/workflows/ci.yml/badge.svg)](https://github.com/sanaddmour-byte/project-M/actions/workflows/ci.yml)

A native iOS field-capture app for construction trade foremen to document
Time & Material (T&M) tickets — extra work directed verbally by a GC — in
under 90 seconds, fully offline, with evidence (photos burned with
location/timestamp/ticket serial, a device-reported signature, a SHA-256
tamper-evidence hash) that holds up in a billing dispute.

This build is **mobile field-capture only**: no backend server, no PM web
dashboard, no live ERP sync, no send capability. Everything is local,
on-device, SwiftData-backed storage. See `DECISIONS.md` for the judgment
calls made while building it, and read that file's first section before
anything else — **this project has not been compiled or run**, because it
was built in an environment with no macOS/Xcode available at all.

## Requirements

- Xcode 15.1+ (Swift 5.10, iOS 17 SDK)
- iOS 17.0+ deployment target
- No CocoaPods, no third-party Swift packages — Apple frameworks only
  (SwiftUI, SwiftData, AVFoundation, Speech, CoreLocation, PDFKit,
  CryptoKit, PencilKit-equivalent via `Canvas`).

## Build & run

```
xcodebuild build -scheme SiteVantage -destination 'platform=iOS Simulator,name=iPhone 15'
```

or open `SiteVantage.xcodeproj` in Xcode and run on an iPhone 15 (or
similar) simulator. **This has not been run — do this first** before
relying on anything else here. If it doesn't build cleanly, that is
expected risk called out in `DECISIONS.md` §0, not a surprise.

### Unit tests

There's a `SiteVantageTests` target covering the pure-logic pieces —
`PricingCalculator`, `FieldItemParser`, `TicketSerialGenerator`,
`NoticeDraftGenerator` — against an in-memory SwiftData store:

```
xcodebuild test -scheme SiteVantage -destination 'platform=iOS Simulator,name=iPhone 15'
```

This is the one part of the acceptance checklist you can get real
pass/fail signal on without touching the UI — worth running before the
simulator UI pass.

### If you add/remove/rename source files

`SiteVantage.xcodeproj/project.pbxproj` was generated by
`scripts/generate_pbxproj.py`, which walks the `SiteVantage/` folder and
emits file references, groups, and build phases for whatever it finds.
After adding/removing/renaming a file under `SiteVantage/`, re-run:

```
python3 scripts/generate_pbxproj.py
```

from the repo root. It also regenerates the shared scheme
(`SiteVantage.xcodeproj/xcshareddata/xcschemes/SiteVantage.xcscheme`) so
the two stay in sync. Requires only the Python 3 standard library.

```
  Models/         SwiftData @Model classes + shared enums
  Services/       Pure logic: pricing, PDF generation, speech, location,
                   photo metadata burn-in, notice drafting, serials
  Views/
    Tickets/      Ticket list, ticket detail, and the 6-screen new-ticket

    Projects/     Project CRUD, rate sheet, notice configuration
    Settings/     Current user, high-contrast toggle, disclaimers
    Shared/       Reusable view helpers (theme, permission UI, share sheet)
  Resources/      Info.plist, Assets.xcassets (incl. the placeholder

                   placeholder floor-plan/app-icon images (not shipped in
                   the app bundle; dev-time tooling only)
DECISIONS.md       Judgment calls made against the underspecified parts
                   of the original spec, including the environment
                   limitation this was built under
```

## Permissions this app requests (and why)

Only three: Camera, Location (When In Use), and Speech Recognition /
Microphone. There is **no** Photo Library usage key anywhere — evidence
photos are captured directly from the live camera and written straight to
the app's own Documents directory; there's no code path that can reach
the Photos library at all.

## Core offline guarantee

Every step of ticket creation — voice capture, on-device transcription,
scope review, camera capture with location/heading burn-in, pricing, and
signature/decline — works with the device in Airplane Mode. Speech
recognition is configured with `requiresOnDeviceRecognition = true` and
there is no networking code anywhere in the core flow. PDF export via the
share sheet is the only "export"; there is no upload.
